Privacy Policy

Information about the public website and the API services currently used or planned by Wahltrends.

Last updated: 23 August 2026

1. Controller and contact details

The operator identified in the Legal Notice is the controller for this website and the Wahltrends API client. The Legal Notice also provides the contact address for privacy enquiries, complaints, revocations, and deletion requests.

2. Public website and GitHub Pages

This website provides information about the privately operated Wahltrends project. It is a static GitHub Pages site and does not provide user accounts, proprietary contact forms, login functions, or embedded social media widgets. Wahltrends does not use its own analytics or tracking services, advertising trackers, or marketing cookies on this site.

When the site is accessed, the browser connects to GitHub. GitHub logs the IP address of GitHub Pages visitors for security purposes and may process further technically necessary usage and access data, in particular the date and time of the request, the page or resource requested, referrer, and device and browser information.

To the extent that this processing is attributable to the operator, its purpose is to provide the website reliably, securely, and without technical errors. The legal basis is Article 6(1)(f) GDPR; the legitimate interest is the secure and functional publication of this information service. GitHub is the recipient and hosting provider. GitHub may process data outside the European Economic Area and describes the safeguards it relies on in its privacy statement.

The operator does not receive proprietary server logs from GitHub Pages and does not store such access data independently. GitHub determines its retention periods according to the relevant processing purpose and legal obligations. Details are available in the GitHub General Privacy Statement ↗.

3. Planned Google Trends API and Wikipedia Pageviews

Wahltrends plans to use the Google Trends API for a weekly “Politicians in Trend” format. Access is currently at the application and alpha stage and has not yet been integrated into Wahltrends production systems.

The intended use is limited to retrieving aggregated trend values for search interest in selected political persons and terms, with a geographic focus on Germany. These aggregated values are planned to be combined with aggregated Wikimedia/Wikipedia page-view statistics in order to calculate a proprietary weekly Wahltrends attention index and rank changes compared with the previous week.

Wahltrends will not use the Google Trends API to obtain individual search queries, Google account data, IP addresses, user identifiers, or other personal data about Google users. Likewise, no individual reader profiles are obtained through the Wikipedia page-view interface. Only aggregated statistical values are processed. They are not used for profiling individual persons or users.

The planned analysis is intended solely to represent public search and information interest. It is not used to determine or predict individual political views. Further information about Google's processing is available in the Google Privacy Policy ↗. Further technical information about the planned use is provided in the Terms and API Information.

4. YouTube API Services and OAuth

Wahltrends uses YouTube API Services. The YouTube API client is not a publicly offered service. It is used exclusively by the operator for the operator's own authorized Wahltrends channel; external visitors cannot authorize a Google or YouTube account through either this website or the client.

Authorization is handled through OAuth and is limited to the permissions granted. The client retrieves the identity of the authorized channel and the status of previously uploaded videos and uploads prepared Wahltrends videos to that channel. When YOUTUBE_PUBLIC_PUBLISHING_ENABLED=true, authorization is valid, and YOUTUBE_CHANNEL_ID matches the authorized channel, public publishing is automatic and requires no per-video confirmation. Private diagnostic runs do not publish publicly.

The OAuth client ID, client secret, and refresh token are supplied through the protected YOUTUBE_CLIENT_ID, YOUTUBE_CLIENT_SECRET, and YOUTUBE_REFRESH_TOKEN environment variables. YOUTUBE_CHANNEL_ID is a non-secret repository variable. Refresh tokens are not stored in Automation State. Access tokens created from the refresh token are held only in memory.

5. Use, protection, and sharing of YouTube data

The data is used solely to confirm the operator's own authorized Wahltrends channel, upload prepared videos, check their YouTube status, and internally record publication. The only YouTube API-derived data stored in Automation State consists of YouTube video IDs in platform publication state, YouTube video IDs in publication-history records, and sanitized YouTube API error text. Channel information is not stored there. Manual diagnostics print channel and video IDs to their execution logs.

The client does not collect or store YouTube login credentials such as usernames or passwords. API Data is not sold, used for advertising or profiling, or disclosed to third parties without authorization. Data is transmitted only to Google or YouTube where required to use YouTube API Services, or where disclosure is legally required.

6. Storage, refresh, and deletion of YouTube API Data

Stored YouTube video IDs and sanitized API error text are deleted 21 calendar days after storage; their retention period is not refreshed. Local cleanup runs during weekly/run and publish-ready and uses no YouTube API quota.

The operator can manually revoke authorization with youtube-revoke. The procedure can first pull bot-state; it then sends the configured refresh token to Google's revocation endpoint, immediately removes all locally stored YouTube API data, records authorization loss in State schema 7, saves and pushes the cleaned state, and reports only sanitized counts. A token that is already invalid does not prevent local cleanup. A failure to persist the cleanup is reported as an error.

Alternatively, access can be revoked through the Google security and account permissions page ↗. If a subsequent OAuth refresh response contains invalid_grant, the client treats it as authorization loss: it immediately removes stored YouTube API data, persists the corresponding marker, and blocks further YouTube uploads. Temporary network failures and HTTP 5xx responses are not treated as revocation. With a new valid refresh token, the next enabled publish-ready run revalidates the configured channel, clears the marker, and resumes automatic publishing.

Internal Wahltrends history remains intact during scheduled cleanup and authorization loss. Candidate IDs, content information, platform status, timestamps, and publication-history records remain stored; only external YouTube IDs and YouTube API errors are removed from them. Facebook and Instagram state is unchanged.

An explicit deletion or revocation request may be submitted using the contact address in the Legal Notice. Neither deletion of local API data nor revocation of OAuth authorization deletes videos stored by YouTube. The client uses no YouTube endpoint for deleting videos or changing their visibility.

8. TikTok Developer Services – not currently active

Wahltrends does not currently use TikTok Developer Services in production. No TikTok API data, access tokens, or refresh tokens are currently processed, no content is automatically published through a TikTok API, and no representation is made that TikTok review, approval, or audit has been successfully completed.

A future integration would be considered only after the necessary technical setup, authorization, and any review or approval required by TikTok. Depending on the feature actually implemented at that time, the following data could be processed solely for authorized content posting: open_id, access token and refresh token, creator information needed for posting, privacy and posting options, post metadata, publishing identifier and status, and the video file to be transferred.

Tokens and secrets would be protected, stored server-side, and kept inaccessible to the public. TikTok data would be used only for the authorized posting purpose, would not be sold or used for advertising or profiling, and would be shared only with TikTok, technically necessary recipients, or as legally required. Authorization would be revocable; data no longer required after revocation or termination would be deleted in accordance with the TikTok rules and legal requirements applicable at that time. Before any production activation, this Privacy Policy will be updated to reflect the actual processing, legal basis, recipients, and retention periods.

9. Data subject rights

Subject to the applicable legal requirements, data subjects have in particular the right of access (Article 15 GDPR), rectification (Article 16 GDPR), erasure (Article 17 GDPR), restriction of processing (Article 18 GDPR), data portability where applicable (Article 20 GDPR), and objection to processing based on legitimate interests (Article 21 GDPR). Consent may be withdrawn with effect for the future.

These rights may be exercised using the contact address in the Legal Notice. Where GitHub processes data under its own responsibility, requests must be directed to GitHub. Under Article 77 GDPR, data subjects also have the right to lodge a complaint with a data protection supervisory authority, in particular in the place of their habitual residence, place of work, or place of the alleged infringement.
